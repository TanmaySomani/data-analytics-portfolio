# Marketing Campaign Analysis: project explanation

## 1. Business question
How do observed term-deposit subscription rates differ across bank telemarketing records?

## 2. Source and scope
Moro, S., Rita, P., & Cortez, P. (2014), Bank Marketing, UCI Machine Learning Repository, https://doi.org/10.24432/C5K306 (CC BY 4.0).

Source documentation: https://archive.ics.uci.edu/dataset/222/bank+marketing

One campaign example in the bank-additional-full.csv sample of a Portuguese bank, May 2008 to November 2010. Multiple contacts can be required for one client.

Included raw file: `raw.csv`. SHA-256: `74adfc578bf77a7ff4bb1ba4a9f8709d9e3c6907342959c2c8416847e0afb4d8`.

## 3. Data dictionary
- y: whether the client subscribed to a term deposit.
- contact: communication type (cellular or telephone).
- campaign: number of contacts in the current campaign for the client.
- poutcome: prior campaign outcome.
- month and day_of_week: timing of last contact; year is not included.
- duration: last contact duration in seconds, only available after contact.
- converted and contact_band: derived in this project.

## 4. Cleaning and quality checks
41,188 campaign records; 0 blank cells; 12,718 source values labeled unknown. 12 identical-looking rows retained because there is no customer ID or event ID.

Review `data/clean.csv.gz` for the analytical records. Duplicate-looking records are not removed without a reliable event identifier. `unknown` categories are retained where present. Quality rules are explicit in `project.py`.

## 5. Metrics and definitions
- Subscription rate = records with y = yes ÷ all records in the segment.
- Contact is the recorded communication type; campaign counts contacts for the client during the current campaign.
- Previous outcome describes the previous campaign and includes a nonexistent category.
- Rates are record-weighted; without customer IDs, unique customers and independent customer-level conversion cannot be calculated.

## 6. Results
| Metric | Value |
|---|---:|
| Campaign records | 41,188 |
| Subscriptions | 4,640 |
| Subscription rate | 11.3% |
| Contact methods | 2 |

### Findings
1. 14.7% of cellular records and 5.2% of telephone records ended in subscription.
2. Records with prior campaign success have 65.1% subscription rate (1,373 records).
3. Overall, 4,640 of 41,188 records indicate a term-deposit subscription.

Detailed segment counts and values are in `outputs/`. Percentages in text and slides are rounded; CSVs retain greater precision.

## 7. Recommendation
Use the differences to design a prospective, randomized channel or contact-strategy test, recording costs, eligibility and incremental subscriptions.

### Next steps
1. Check campaign eligibility and contact histories before comparing audience groups.
2. Avoid using call duration as a predictor before the call; review sensitive attributes and fair treatment.
3. Randomize a channel strategy and collect spend and margin before estimating incremental ROI.

## 8. Limitations and interpretation
The source records phone campaigns, not paid search or social. It has no spend, revenue, cost or randomized assignment: CPA, ROAS and incremental effect cannot be computed. Channel and previous-campaign comparisons are observational and may reflect targeting or economic conditions. Last-call duration is known only after a call and must not be used for pre-call targeting. The data is historical.

These findings describe the supplied historical data; they should not be presented as results for another company or as causal effects.

## 9. Reproduce the analysis
1. Install Python 3.9+ and the dependency: `python3 -m pip install -r requirements.txt`.
2. From the project folder, run `python3 project.py`. The included source file is read locally; no network connection is needed.
3. Review `outputs/summary.json`, the segment CSVs and `data/clean.csv.gz`. Re-running overwrites generated outputs and this explanation but preserves the raw source file.
4. Open `presentation.pptx`. The deck is a snapshot of this analysis and is not automatically regenerated by `project.py`.

## 11. Run the interactive dashboard

From a terminal opened in this project folder, create and activate a virtual environment, then install the dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows, activate the environment with `.venv\Scripts\activate` instead. The initial installation requires internet access. Then start the dashboard:

```bash
python -m streamlit run dashboard.py --server.address 127.0.0.1
```

Open the local URL printed in the terminal (normally `http://localhost:8501`). Stop the server with Ctrl+C. To run another dashboard at the same time, use a different port, for example append `--server.port 8502`. The dashboard reads the included local files and does not need internet access after installation. If an analysis output is missing, run `python project.py` first.

Filter by contact method, previous campaign outcome, and current-campaign contact count. Choose a segment for the subscription-rate comparison and download the displayed summary. The records do not include marketing spend, unique customer IDs, or incremental lift.

Changes to filter selections affect the dashboard only. Run `python project.py` to rebuild the cleaned data and analysis outputs from the included source; the dashboard detects the updated files. The presentation remains a separate snapshot and is not rebuilt by the dashboard or analysis script.
