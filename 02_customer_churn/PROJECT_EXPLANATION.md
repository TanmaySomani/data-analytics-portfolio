# Customer Churn Analysis: project explanation

## 1. Business question
Which customer characteristics are associated with churn in an observed telecom customer sample?

## 2. Source and scope
Iranian Churn (2020), UCI Machine Learning Repository, https://doi.org/10.24432/C5JW3Z (CC BY 4.0).

Source documentation: https://archive.ics.uci.edu/dataset/563/iranian+churn+dataset

One customer per record from an Iranian telecom company. Features aggregate the first nine months; the label records customer status at the end of 12 months.

Included raw file: `raw.csv`. SHA-256: `90d5fb6bd1630cd4de4b4d28fcf8b4cb92a8f6ab7484605b0799d47386f7dbe1`.

## 3. Data dictionary
- Churn: binary outcome (1 churn; 0 non-churn).
- Complains: binary complaint indicator.
- Subscription Length: total months of subscription.
- Tariff Plan: 1 pay as you go; 2 contractual.
- Call Failure, Seconds of Use, Frequency of use and Frequency of SMS: observed service measures.
- Status: source active/non-active code; Customer Value: source-calculated value with unspecified formula.

## 4. Cleaning and quality checks
3,150 customer rows; 0 missing cells; 300 identical feature rows retained because the dataset provides no unique customer identifier.

Review `data/clean.csv.gz` for the analytical records. Duplicate-looking records are not removed without a reliable event identifier. `unknown` categories are retained where present. Quality rules are explicit in `project.py`.

## 5. Metrics and definitions
- Churn rate = number with Churn = 1 ÷ number of customer records in the segment.
- Complains: 1 indicates a complaint; 0 indicates no complaint.
- Tariff Plan: 1 = pay as you go; 2 = contractual.
- Subscription length bands use 0–6, 7–12, 13–24 and 25+ months.

## 6. Results
| Metric | Value |
|---|---:|
| Customers | 3,150 |
| Churn labels | 495 |
| Observed churn rate | 15.7% |
| With complaint | 241 |

### Findings
1. Customers with a recorded complaint had 83.0% churn versus 10.1% without one.
2. Pay-as-you-go tariff group (code 1) has 16.8% churn.
3. The dataset identifies 495 churned customers among 3,150 records.

Detailed segment counts and values are in `outputs/`. Percentages in text and slides are rounded; CSVs retain greater precision.

## 7. Recommendation
Investigate service issues behind complaints, then test a support intervention with a randomized holdout and measure incremental retention.

### Next steps
1. Validate event definitions, the label construction and feature timing with the source owner.
2. Compare complaint and churn associations within tariff and tenure bands.
3. Run a randomized intervention with a measured cost and a pre-specified retention outcome.

## 8. Limitations and interpretation
The data is a sample from one telecom provider and the collection calendar is not specified. Complaint, usage and tariff associations do not prove why customers leave; selection and other differences may explain them. Status may contain outcome-related information, so review its timing before predictive use. Customer Value has an unspecified calculation and is not treated as revenue.

These findings describe the supplied historical data; they should not be presented as results for another company or as causal effects.

## 9. Reproduce the analysis
1. Install Python 3.9+ and the dependency: `python3 -m pip install -r requirements.txt`.
2. From the project folder, run `python3 project.py`. The included source file is read locally; no network connection is needed.
3. Review `outputs/summary.json`, the segment CSVs and `data/clean.csv.gz`. Re-running overwrites generated outputs and this explanation but preserves the raw source file.
4. Open `presentation.pptx`. The deck is a snapshot of this analysis and is not automatically regenerated by `project.py`.

## 11. Run the interactive dashboard

From a terminal opened in this project folder, create and activate a virtual environment, then install the dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows, activate the environment with `.venv\Scripts\activate` instead. The initial installation requires internet access. Then start the dashboard:

```bash
python -m streamlit run dashboard.py --server.address 127.0.0.1
```

Open the local URL printed in the terminal (normally `http://localhost:8501`). Stop the server with Ctrl+C. To run another dashboard at the same time, use a different port, for example append `--server.port 8502`. The dashboard reads the included local files and does not need internet access after installation. If an analysis output is missing, run `python project.py` first.

Filter by tariff, complaint status, and subscription length. Change the comparison to complaint status, tariff, or tenure band. The chart and downloadable table show both the churn rate and the number of records behind it. Associations do not establish causes.

Changes to filter selections affect the dashboard only. Run `python project.py` to rebuild the cleaned data and analysis outputs from the included source; the dashboard detects the updated files. The presentation remains a separate snapshot and is not rebuilt by the dashboard or analysis script.
