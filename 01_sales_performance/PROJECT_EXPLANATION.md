# Sales Performance Analysis: project explanation

## 1. Business question
How did an online retailer’s observed invoice-line value vary by country, product and month?

## 2. Source and scope
Chen, D. (2015), Online Retail, UCI Machine Learning Repository, https://doi.org/10.24432/C5BW33 (CC BY 4.0).

Source documentation: https://archive.ics.uci.edu/dataset/352/online+retail

One row per invoice line for a UK-based online retailer, 1 Dec 2010 to 9 Dec 2011. The company sells gifts and includes wholesale customers.

Included raw file: `raw.csv.gz`. SHA-256: `95e7ce0123134e1a0c44aeb0fc1632048a35a1c96d5d57ec727534ae6d02d27d`.

The included compressed CSV is a conversion of the original UCI workbook. Both retail projects use the same source for different questions; they are not independent datasets.

## 3. Data dictionary
- InvoiceNo: invoice identifier; a C prefix indicates cancellation.
- StockCode and Description: product code and source description.
- Quantity and UnitPrice: line quantity and unit price in pounds.
- InvoiceDate: transaction date and time.
- CustomerID: customer identifier, missing on some lines; Country: customer country.
- line_value and month: derived in this project.

## 4. Cleaning and quality checks
541,909 source lines; 9,288 cancellation-prefixed lines; 11,805 nonpositive quantity or price lines; 11,805 excluded by either rule; 135,080 source lines lack customer ID. These categories overlap. 5,268 exact duplicate-looking rows are retained because they may represent distinct invoice lines.

Review `data/clean.csv.gz` for the analytical records. Duplicate-looking records are not removed without a reliable event identifier. `unknown` categories are retained where present. Quality rules are explicit in `project.py`.

## 5. Metrics and definitions
- Included line value = Quantity × UnitPrice in pounds, restricted to non-cancellation lines with positive quantity and unit price.
- Invoices = distinct InvoiceNo among included lines; it is not necessarily a count of unique customers.
- Country share = included country line value ÷ all included line value.
- Monthly comparisons use calendar months; December 2010 and December 2011 are incomplete.

## 6. Results
| Metric | Value |
|---|---:|
| Positive line value | £10,666,685 |
| Invoices | 19,960 |
| Sales lines | 530,104 |
| Countries | 38 |

### Findings
1. United Kingdom accounts for 84.6% of included line value.
2. The highest-value stock code is DOT, at £206,249.
3. 2011-11 has the largest included line value at £1,509,496.

Detailed segment counts and values are in `outputs/`. Percentages in text and slides are rounded; CSVs retain greater precision.

## 7. Recommendation
Review high-value products and markets with the retailer’s returns, product costs and fulfilment data before deciding where to change pricing or inventory.

### Next steps
1. Reconcile invoices, cancellations and credit notes with accounting records.
2. Join product cost, delivery fees and returns to calculate contribution margin.
3. Investigate seasonal demand using complete comparable months and more years of data.

## 8. Limitations and interpretation
This is positive invoice-line value, not net revenue: cancelled and negative lines are excluded rather than matched back to orders. Prices and amounts may include postage, fees and unusual adjustments. There is no product cost, so profit, margin and loss-making products cannot be computed. The dataset is historical and from a single retailer.

These findings describe the supplied historical data; they should not be presented as results for another company or as causal effects.

## 9. Reproduce the analysis
1. Install Python 3.9+ and the dependency: `python3 -m pip install -r requirements.txt`.
2. From the project folder, run `python3 project.py`. The included source file is read locally; no network connection is needed.
3. Review `outputs/summary.json`, the segment CSVs and `data/clean.csv.gz`. Re-running overwrites generated outputs and this explanation but preserves the raw source file.
4. Open `presentation.pptx`. The deck is a snapshot of this analysis and is not automatically regenerated by `project.py`.

## 11. Run the interactive dashboard

From a terminal opened in this project folder, create and activate a virtual environment, then install the dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows, activate the environment with `.venv\Scripts\activate` instead. The initial installation requires internet access. Then start the dashboard:

```bash
python -m streamlit run dashboard.py --server.address 127.0.0.1
```

Open the local URL printed in the terminal (normally `http://localhost:8501`). Stop the server with Ctrl+C. To run another dashboard at the same time, use a different port, for example append `--server.port 8502`. The dashboard reads the included local files and does not need internet access after installation. If an analysis output is missing, run `python project.py` first.

Filter by invoice month, customer country, and optional stock-code or description text. The totals, monthly chart, country chart, and stock-code table update together. Download the filtered stock-code table as CSV. Codes may include postage and fees; line value is not profit or net revenue.

Changes to filter selections affect the dashboard only. Run `python project.py` to rebuild the cleaned data and analysis outputs from the included source; the dashboard detects the updated files. The presentation remains a separate snapshot and is not rebuilt by the dashboard or analysis script.
